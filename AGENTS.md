# AGENTS.md

Правила для AI-агентов, работающих в этом репозитории.

## Назначение

Отдел идей в формате HTML: каждая идея — папка с PRD и HTML-«центром», внутри — варианты визуализации. Цель — быстро прогонять идеи в HTML и сравнивать направления.

## Реестр идей

**[index.md](index.md)** — обязательный реестр: номер, название, дата, статус, ссылки на папку, PRD и центр.

При добавлении, изменении статуса или архивации идеи — **обновляй `index.md`** в том же коммите.

## Топология

```
/
├── index.html         # Галерея: три версии главной (home/v1–v3) + идея 001
├── home/              # Варианты главной страницы отдела (опционально)
│   ├── prd.md
│   └── v<N>/          # index.html + brief.md
├── index.md           # Реестр идей для агента (источник инвентаризации)
├── README.md          # Карточка отдела для людей
├── AGENTS.md          # Этот файл
└── ideas/
    └── NNN-<slug>/    # Одна идея
        ├── prd.md     # Микро-PRD (источник правды для идеи)
        ├── index.html # Галерея: описание идеи + карточки вариантов
        └── v<N>/      # Варианты визуализации (опционально)
            ├── index.html   # лендинг; nav: ../index.html, brief.md
            └── brief.md
```

## Навигация HTML

- **Корневой `index.html`** — при новой идее добавь строку с ссылками на галерею и `prd.md`.
- **Галерея** (`ideas/NNN-…/index.html`) — у каждого `v<N>` две ссылки: `v<N>/index.html` (страница) и `v<N>/brief.md` (бриф). Footer: `../../index.html` (отдел).
- **Вариант** — в `<nav>` вверху: `../index.html` («Галерея идеи») и `brief.md` («Бриф vN»).
- Все `href` — относительные пути для HTML внутри репо; **ссылки «PRD»** в интерфейсе ведут на GitHub: `https://github.com/serejaris/x26-ideas/blob/main/…/prd.md` (`target="_blank"`).
- Перед коммитом проверь, что локальные пути существуют.

## Конвенции для идеи

- Папка: `ideas/NNN-<slug>/` (`NNN` — 001, 002, …; `<slug>` — kebab-case).
- Обязательно: `prd.md` и `index.html` (центр).
- Опционально: `v<N>/` с вариантами визуализации.

## Конвенции для вариантов

- Каждый вариант = отдельная папка `v<N>/` внутри идеи.
- Внутри строго два файла: `index.html` и `brief.md`.
- `brief.md` варианта = исходный `prd.md` (без правок) + секция «Дизайн-решения этой версии» внизу.
- Один HTML-файл на вариант, без сборки и без зависимостей.
- Tailwind подключается ТОЛЬКО через CDN: `<script src="https://cdn.tailwindcss.com"></script>`.
- НЕТ кастомных стилей: ни `<style>` блоков, ни инлайн `style=""`. Всё оформление через Tailwind-классы.
- Семантический HTML: `<header>`, `<section>`, `<footer>`, осмысленные заголовки.
- Адаптив mobile-first (`md:`, `lg:` классы).
- Плейсхолдеры для контактов: `https://t.me/your_handle` (не вставлять реальные хэндлы без явной просьбы).

## Безопасные действия (без подтверждения)

- Создавать новую идею `ideas/NNN-<slug>/` с `prd.md` и `index.html`.
- Создавать новые варианты `v<N>/` с двумя файлами по конвенции.
- Править HTML и `brief.md` внутри существующего варианта.
- Обновлять `index.html` центра идеи при добавлении варианта.
- Обновлять **[index.md](index.md)** при изменении инвентаря идей.
- Обновлять `README.md` при изменении общей картины отдела.
- Обновлять корневой `index.html` при добавлении идеи.

## Требуют подтверждения

- Удаление существующей идеи или варианта `v<N>/`.
- Изменение `prd.md` существенно по смыслу (источник правды для идеи и всех её вариантов).
- Смена конвенций (например, отход от Tailwind CDN).
- Добавление любых зависимостей или билд-системы.

## Запрещено

- Коммитить секреты, токены, ключи, личные хэндлы и контакты.
- Писать кастомный CSS в файлах вариантов (см. правило про Tailwind).
- Подключать сторонние JS-библиотеки в варианты без явного запроса.
- Исключение: `home/v6/` и `home/v7/` — разрешён **D3 v7** через CDN для графа библиотеки идей.
- Использовать `git push --force` к `main` / `master`.
- Менять `.git/config` от имени агента.

## Запуск нескольких вариантов параллельно

Когда задача — сгенерировать N направлений дизайна для одной идеи:

- Использовать параллельных субагентов, по одному на вариант.
- Каждому субагенту передавать полный `prd.md` + конкретное дизайн-направление + ограничения (Tailwind CDN, без кастомных стилей).
- Каждый субагент работает только внутри своей папки `ideas/NNN-<slug>/v<N>/`.

## Проверка результата

- Открыть центр идеи или вариант в браузере: `open ideas/NNN-<slug>/index.html`.
- Глазами проверить адаптив (mobile + desktop).
- Убедиться, что в файле нет `<style>` и `style="..."`.

## Конвенции коммитов

- Короткие императивные заголовки на русском или английском.
- Один логический шаг = один коммит.
- Не коммитить `node_modules/`, `.env*`, бэкапы и черновики (`.gitignore` уже это покрывает).

## Когда сомневаешься

1. Сверься с **[index.md](index.md)** — какие идеи есть и какой у них статус.
2. Сверься с `prd.md` конкретной идеи — он определяет тон, аудиторию и цель.
3. Всё, что противоречит PRD, обсуждаем перед изменением.

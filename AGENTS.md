# AGENTS.md

Правила для AI-агентов, работающих в этом репозитории.

## Назначение

Песочница для дизайн-исследований лендингов и прототипов. Один проект (бриф) → несколько визуальных вариантов в отдельных папках. Цель — быстро прогонять идеи в HTML и сравнивать направления.

## Топология

```
/
├── brief.md           # Исходный бриф текущего проекта (источник правды)
├── index.html         # Галерея вариантов
├── v1/, v2/, v3/, ... # Дизайн-варианты, по одному на папку
│   ├── index.html     # Лендинг
│   └── brief.md       # Копия исходного брифа + секция «Дизайн-решения этой версии»
└── README.md          # Карточка проекта
```

## Конвенции для вариантов

- Каждый вариант = отдельная папка `v<N>/`.
- Внутри строго два файла: `index.html` и `brief.md`.
- `brief.md` варианта = исходный `brief.md` (без правок) + секция «Дизайн-решения этой версии» внизу.
- Один HTML-файл на вариант, без сборки и без зависимостей.
- Tailwind подключается ТОЛЬКО через CDN: `<script src="https://cdn.tailwindcss.com"></script>`.
- НЕТ кастомных стилей: ни `<style>` блоков, ни инлайн `style=""`. Всё оформление через Tailwind-классы.
- Семантический HTML: `<header>`, `<section>`, `<footer>`, осмысленные заголовки.
- Адаптив mobile-first (`md:`, `lg:` классы).
- Плейсхолдеры для контактов: `https://t.me/your_handle` (не вставлять реальные хэндлы без явной просьбы).

## Безопасные действия (без подтверждения)

- Создавать новые варианты `v<N>/` с двумя файлами по конвенции.
- Править HTML и `brief.md` внутри существующего варианта.
- Обновлять `index.html` галереи при добавлении нового варианта.
- Обновлять `README.md` при изменении общей картины проекта.

## Требуют подтверждения

- Удаление существующего варианта `v<N>/`.
- Изменение исходного `brief.md` в корне (это источник правды для всех вариантов).
- Смена конвенций (например, отход от Tailwind CDN).
- Добавление любых зависимостей или билд-системы.

## Запрещено

- Коммитить секреты, токены, ключи, личные хэндлы и контакты.
- Писать кастомный CSS в файлах вариантов (см. правило про Tailwind).
- Подключать сторонние JS-библиотеки в варианты без явного запроса.
- Использовать `git push --force` к `main` / `master`.
- Менять `.git/config` от имени агента.

## Запуск нескольких вариантов параллельно

Когда задача — сгенерировать N направлений дизайна:

- Использовать параллельных субагентов, по одному на вариант.
- Каждому субагенту передавать полный бриф + конкретное дизайн-направление + ограничения (Tailwind CDN, без кастомных стилей).
- Каждый субагент работает только внутри своей папки `v<N>/`.

## Проверка результата

- Открыть `index.html` варианта или корневую галерею в браузере: `open <path>`.
- Глазами проверить адаптив (mobile + desktop).
- Убедиться, что в файле нет `<style>` и `style="..."`.

## Конвенции коммитов

- Короткие императивные заголовки на русском или английском.
- Один логический шаг = один коммит.
- Не коммитить `node_modules/`, `.env*`, бэкапы и черновики (`.gitignore` уже это покрывает).

## Когда сомневаешься

Сверься с `brief.md` в корне — он определяет тон, аудиторию и цель. Всё, что противоречит брифу, обсуждаем перед изменением.
